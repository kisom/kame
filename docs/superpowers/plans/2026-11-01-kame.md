# kame Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build kame, a WYSIWYG prose editor with anchored marginalia/notes/footnotes, SQLite-backed persistent undo + snapshots, and markdown/HTML export.

**Architecture:** A pure-Rust core (document model → SQLite storage → cosmic-text layout → swash rasterization → export) is built and headless-tested first; an egui immediate-mode shell is layered on last. All text offsets are byte offsets; every mutation is an invertible `Op` that maintains the anchor invariant and is appended to a durable op log.

**Tech Stack:** Rust, eframe/egui 0.37.0, cosmic-text 0.19.0 (swash feature), swash 0.2.10, rusqlite 0.41.1 (bundled), serde 1.0 / serde_json 1.0, uuid 1.29, image 0.25.10.

**Spec:** `docs/superpowers/specs/2026-11-01-kame-design.md`

## Global Constraints

- Rust. All text offsets are **byte offsets** (`str` indices), matching cosmic-text `glyph.start`/`end`.
- Every text mutation goes through an edit command that produces an invertible `Op` and maintains the anchor invariant (anchors in the edited block shift by the edit delta when the edit point precedes them).
- Body text shapes with `Shaping::Advanced` + `Align::Justified`; Crimson Pro for headings, EB Garamond for body.
- SQLite in WAL mode, `PRAGMA user_version` for schema migration.
- Deterministic markdown/HTML export (byte-identical for identical documents).
- Targets Linux (Arch) + macOS; no Windows.
- Deps pinned as in the Tech Stack; no new runtime deps without a spec change.
- On straylight (NixOS, no cargo on PATH) prefix cargo commands with `nix-shell -p cargo rustc gcc --run`; elsewhere use bare `cargo`.

## Review Focus

The five inputs the spec is silent on that would most likely bite a user, in order:

1. **Multibyte text near an anchor** — em-dashes, curly quotes, or non-Latin text edited *before* an anchored note must not misanchor it. (byte-vs-char index bug.)
2. **Empty document / empty block** — a brand-new doc, or deleting all text in a paragraph, must load, layout, and export without panicking.
3. **Annotation orphaned by block deletion** — deleting the block an annotation is anchored to must not leave a dangling anchor; undo must restore it.
4. **Undo across save/close/reopen** — undo after reopening must produce the identical state as undoing in-session (the op log, not the saved blob, is the source of truth).
5. **Export churn** — exporting the same document twice (including after a save/load round-trip) must be byte-identical, or git history of the export is noise.

Each maps to a test in the owning task below (tasks 3, 2/4, 5, 5, and 13/14 respectively).

**Files:**

- Create: `src/edit/editor.rs` (the in-memory `Editor`)
- Modify: `src/storage/db.rs` (append/read/truncate ops), `src/edit/mod.rs`, `src/storage/mod.rs`
- Test: `src/edit/ops.rs`, `src/edit/editor.rs`

**Interfaces:**
- Consumes: model (Task 2), anchor (Task 3), storage (Task 4).
- Produces:
  - `pub enum Op { InsertText { block_id: BlockId, offset: usize, text: String }, DeleteText { block_id: BlockId, start: usize, end: usize, text: String }, InsertBlock { index: usize, block: Block }, DeleteBlock { index: usize, block: Block, annotations: Vec<Annotation> }, SetBlockKind { block_id: BlockId, kind: BlockKind }, AddAnnotation { annotation: Annotation }, RemoveAnnotation { annotation: Annotation }, SetTitle { old: String, new: String } }` (derive `Clone, Debug, PartialEq, Serialize, Deserialize`)
  - `pub fn invert(op: &Op) -> Op;`
  - `pub fn apply(doc: &mut Document, op: &Op);` — applies the op; `InsertText`/`DeleteText` call `shift_anchors`; `DeleteText` also removes annotations whose anchor lies inside `[start, end)`; `DeleteBlock` removes the block and its anchored annotations (already carried in the op payload).
  - `pub struct Editor { doc: Document, undo: Vec<Op>, redo: Vec<Op> }`
  - `impl Editor { pub fn new(doc: Document) -> Editor; pub fn document(&self) -> &Document; pub fn apply_edit(&mut self, op: Op) -> Op; pub fn undo(&mut self) -> Option<Op>; pub fn redo(&mut self) -> Option<Op>; pub fn history(&self) -> (usize, usize); }` — `apply_edit` applies `op` to the doc, pushes it on `undo`, clears `redo`, and returns the op (the caller persists it). `undo` pops `undo`, applies `invert`, pushes onto `redo`. `redo` symmetric.
  - Storage additions: `pub fn append_op(&mut self, op: &Op) -> Result<i64, Error>; pub fn load_ops(&self) -> Result<Vec<(i64, Op)>, Error>; pub fn truncate_ops_after(&mut self, seq: i64) -> Result<(), Error>;` — `ops(seq INTEGER PRIMARY KEY AUTOINCREMENT, json TEXT)`.

  **History model (deviation from spec's "append-only", flag to reviewer):** the log is linear. Undo/redo move an in-memory cursor over the loaded log; a new edit after undo **truncates** the redo tail (`truncate_ops_after`) so the log stays linear. Branch retention is a possible later enhancement; snapshots remain the no-loss safety net.
