Feedback from a user (these are all things the user would like to see
in a releasable KAME):

1. Arrow keys don't work to move between paragraphs. Up and down-arrow,
   for example should support going between paragraphs.
2. Also the usage text should be in a help dialog, not in the UI. The UI
   in general needs to be simplified. Formatting options should maybe be
   moved to a right click menu? Also, the formatting should probably be
   done markdown style, as in typing '## This is a section' at the start
   of a line, the '## ' should trigger a formatting change to H2.
3. The keybindings are a little weird; I'd expect as a user to have at
   least C-a (and you can say C-a selects just everything in the block,
   and maybe C-a C-a or some other combination selects the entire main
   text).
4. kame should support opening a markdown file, or importing one a new
   kame file. This means supporting the usual open & close file inside
   the UI. I imagine, for example, an "anonymous" new document is an
   in-memory sqlite database that then gets written out to disk upon
   save.
5. Marginals: there's no mechanism for deleting or moving marginals.
   Right click is reasonable. C-m is a reasonable shortcut for adding a
   new marginal. Saving an empty marginal should remove it, too.
6. No search ability. I have no way to search across the body, not to
   mention marginals, notes, or footnotes.
7. Footnotes and notes should have keyboard shortcuts.
8. A main text wordcount would be nice.
9. There a bunch of other minor usability issues: double clicking a word
   should select the word, shift+arrow should be used to select text,
   there's no bold or italic text.
10. Consider changing the note so that it starts as a generic highlight
    (with an optional comment). This mirrors e.g., how the Kindle does
    it.
11. Lists don't appear to work at all either.
12. Engineering note: there doesn't appear to be any testing at all.
13. Engineering note: documents don't appear to be versioned at all
    (that is, kame format v1, for example).
14. There's no README, user instructions, or anything similar.
